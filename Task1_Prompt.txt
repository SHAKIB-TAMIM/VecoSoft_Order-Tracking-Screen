PROMPT 01 — COMPLETE IMPLEMENTATION BRIEF

I am completing a frontend developer assessment. I need you to build the actual frontend implementation, not just provide a plan.

The assessment is for a modern e-commerce ORDER TRACKING SCREEN.

The evaluator will judge the visual quality, UX clarity, responsiveness, interactions, and how well the UI handles the required order states.

==================================================
1. CORE ASSESSMENT REQUIREMENT
==================================================

Build one polished, modern, professional Order Tracking experience for an e-commerce application.

The existing application currently has these delivery statuses:

- Processing
- Shipped
- Out for Delivery
- Delivered

The problem is that users find the current status difficult to understand.

Redesign the experience so the customer can understand the order situation immediately without having to interpret technical status labels.

The experience must clearly communicate:

- What is happening with the order
- Where the order currently is in the delivery journey
- What happened previously
- What happens next
- When the customer should expect delivery
- What the customer can do if something goes wrong

The result should feel like a real production e-commerce application, not a coding exercise or generic dashboard.

==================================================
2. IMPORTANT — THREE REQUIRED ORDER STATES
==================================================

The SAME reusable Order Tracking screen must support all THREE of these states.

Do NOT create three unrelated pages.

The layout, components, hierarchy, and visual system should remain consistent while the content, status messaging, timeline state, alerts, and actions adapt intelligently.

--------------------------------------------------
STATE A — DELAYED ORDER
--------------------------------------------------

Scenario:

The estimated delivery time has passed or the order is significantly delayed.

The customer should immediately understand:

- The order is delayed
- The original expected delivery time
- That the order is still being handled
- What the customer should do next

Design requirements:

- Clearly distinguish the delayed state from normal delivery
- Use a prominent but tasteful status/alert treatment
- Explain the delay in human-friendly language
- Show the latest known tracking event
- Show the original estimated delivery date/time
- Show an updated estimate if appropriate
- Provide a clear next step
- Provide a support/contact option
- Provide a "Report delivery issue" or equivalent action where appropriate

Example UX copy direction:

"Your order is taking a little longer than expected."

"Originally expected Tuesday, Sep 22"

"Updated delivery estimate: Wednesday, Sep 24"

"Latest update: Package is still in transit."

Do not blindly copy this wording if a better UX message can be created.

The state should feel informative and reassuring rather than alarming.

--------------------------------------------------
STATE B — DELIVERED BUT NOT RECEIVED
--------------------------------------------------

Scenario:

The system says the order was delivered, but the customer reports that they did not receive it.

This is NOT a normal Delivered state.

The UI must clearly acknowledge the customer's problem.

The screen should communicate:

- System delivery status
- Delivery date/time
- That the customer reported not receiving the package
- Appropriate troubleshooting/next steps
- A clear support/reporting action

Possible helpful information:

- "Marked delivered"
- Delivery timestamp
- Delivery location if mock data is appropriate
- "Check around your delivery location"
- "Check with household members/neighbors"
- "Report a missing package"
- "Contact support"

Do not make the customer search through the normal timeline to figure out what to do.

The issue/action area should be visually obvious.

--------------------------------------------------
STATE C — TRACKING NOT AVAILABLE YET
--------------------------------------------------

Scenario:

The order exists, but tracking information is not available yet.

Do NOT show a blank page.

Do NOT show a broken-looking empty state.

Do NOT show a fake timeline pretending that tracking events exist.

Instead provide a useful, polished waiting state.

Show:

- Order information
- Product summary
- Order date
- Current order preparation/processing status
- A clear explanation that tracking information is not available yet
- Expected timeframe for tracking to become available, if appropriate
- A useful next step
- Support access

Example UX direction:

"Tracking information isn't available yet."

"Your order has been confirmed and is being prepared. Tracking will appear once your package is handed to the carrier."

Possible action:

"Contact support"

or

"View order details"

The screen should still feel complete and intentional.
